# Conhecimento de UX

## Finalidade

Este domínio reúne conhecimento de referência para apoiar decisões relacionadas à experiência do usuário durante o ciclo de desenvolvimento de software.

UX deve ser compreendida como uma disciplina orientada à compreensão das pessoas, suas necessidades, objetivos, contextos e interações com produtos e serviços.

UX não se limita à aparência visual de uma interface.

## Escopo

Este domínio contempla:

- pesquisa com usuários;
- necessidades e comportamentos;
- jornadas;
- arquitetura da informação;
- usabilidade;
- heurísticas;
- interação;
- prototipação;
- acessibilidade;
- design systems.

## Princípios

A squad deve considerar:

1. compreender o usuário antes de presumir suas necessidades;
2. considerar contexto de uso;
3. distinguir problema de solução;
4. utilizar evidências sempre que possível;
5. reduzir complexidade desnecessária;
6. tornar informações compreensíveis e encontráveis;
7. projetar interações previsíveis;
8. considerar acessibilidade desde o início;
9. validar decisões importantes;
10. tratar UX como parte do produto, não como etapa exclusivamente visual.

## Relação com outros domínios

UX possui relação direta com:

- Produto;
- Processos;
- Engenharia;
- Arquitetura;
- Qualidade;
- Segurança;
- Dados.

Decisões de UX podem afetar requisitos, arquitetura, modelo de dados, segurança, acessibilidade, métricas e operação.

## Relação com skills

Os documentos deste diretório representam conhecimento.

Eles não substituem:

- skills;
- workflows;
- agents;
- commands.

Uma skill pode utilizar este conhecimento para executar uma atividade específica, enquanto este domínio permanece como referência conceitual.

## Governança

Conhecimentos devem ser revisados quando:

- novas evidências relevantes surgirem;
- princípios forem atualizados;
- práticas da squad demonstrarem necessidade de mudança;
- houver conflito entre conhecimento existente e decisões consolidadas;
- uma referência se tornar inadequada ou obsoleta.
