# Design System

## Conceito

Um design system é um sistema organizado de princípios, padrões, componentes, decisões e recursos que ajudam a produzir experiências consistentes e evolutivas.

Ele é mais amplo que uma biblioteca visual de componentes.

## Elementos possíveis

Um design system pode incluir:

- princípios;
- tokens;
- padrões;
- componentes;
- estados;
- comportamento;
- conteúdo;
- acessibilidade;
- documentação;
- critérios de uso.

## Consistência

O objetivo não é tornar todas as partes do produto idênticas.

A consistência deve ajudar o usuário a reconhecer padrões e prever comportamentos.

## Reutilização

Reutilização pode reduzir:

- inconsistência;
- esforço duplicado;
- tempo de desenvolvimento;
- divergência entre interfaces.

Porém, reutilização indiscriminada também pode gerar abstrações inadequadas.

## Componente versus padrão

Um componente representa uma unidade reutilizável de interface ou comportamento.

Um padrão representa uma solução recorrente para determinado problema de experiência.

Nem todo problema deve ser resolvido criando um novo componente.

## Governança

Um design system precisa evoluir.

Isso envolve decisões sobre:

- criação;
- adoção;
- alteração;
- versionamento;
- compatibilidade;
- depreciação;
- documentação.

## Acessibilidade

Acessibilidade deve fazer parte do design system sempre que possível.

Componentes compartilhados podem ajudar a incorporar boas práticas de acessibilidade de maneira consistente.

## Design system e produto

Um design system não deve substituir decisões de produto.

Ele fornece meios reutilizáveis para implementar experiências coerentes.

O contexto do usuário e o problema continuam determinando quais padrões são apropriados.

## Design system e engenharia

A implementação de componentes precisa considerar:

- comportamento;
- acessibilidade;
- desempenho;
- manutenção;
- compatibilidade;
- versionamento.

Portanto, design system é uma área de colaboração entre UX, produto e engenharia.

## Evolução

Um design system saudável evita tanto:

- duplicação desnecessária;

quanto:

- abstração prematura.

A maturidade está em criar padrões reutilizáveis quando existe evidência suficiente de recorrência e valor.
