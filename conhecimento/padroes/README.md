# Padrões da Squad

Esta categoria reúne padrões que podem ser utilizados quando a squad encontrar problemas ou contextos recorrentes.

## O que é um padrão

Um padrão descreve uma abordagem recorrente que pode ser útil em determinado contexto.

Um padrão não deve ser tratado como regra universal.

A decisão de utilizá-lo depende de:

- contexto;
- problema;
- restrições;
- riscos;
- custos;
- benefícios;
- alternativas.

## Estrutura dos padrões

Sempre que aplicável, um padrão deve explicar:

1. problema;
2. contexto;
3. intenção;
4. solução;
5. benefícios;
6. custos;
7. riscos;
8. consequências;
9. quando utilizar;
10. quando evitar;
11. alternativas.

## Padrão não é implementação

Um padrão pode ser aplicado utilizando tecnologias diferentes.

A squad deve compreender primeiro o problema que o padrão resolve.

A tecnologia escolhida posteriormente deve respeitar as necessidades reais do contexto.

## Padrão versus princípio

Princípio orienta decisões.

Padrão apresenta uma solução recorrente para determinado problema.

## Padrão versus arquitetura

Um padrão pode contribuir para uma arquitetura, mas não representa sozinho a arquitetura completa de um sistema.

## Uso consciente

A adoção de um padrão deve ser justificada quando adicionar:

- complexidade;
- dependências;
- infraestrutura;
- operação;
- manutenção;
- custo.

Soluções simples devem continuar sendo preferidas quando atendem adequadamente ao problema.
