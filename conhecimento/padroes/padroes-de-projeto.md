# Padrões de Projeto

Padrões de projeto são soluções recorrentes para problemas de estrutura ou comportamento dentro de sistemas de software.

## Objetivo

Seu objetivo é fornecer vocabulário e abordagens reutilizáveis para problemas conhecidos.

## Categorias conceituais

Podem existir padrões relacionados a:

- criação;
- composição;
- comportamento;
- comunicação;
- integração;
- persistência;
- concorrência;
- resiliência;
- evolução.

## Uso

Um padrão deve ser adotado porque resolve um problema concreto.

Não deve ser utilizado apenas porque:

- é conhecido;
- é considerado sofisticado;
- aparece em outro projeto;
- parece arquiteturalmente elegante.

## Custo

Todo padrão pode introduzir:

- abstrações;
- indireção;
- complexidade;
- manutenção adicional;
- necessidade de conhecimento especializado.

## Regra prática

Antes de adotar um padrão, responder:

1. qual problema existe?
2. por que a solução simples não é suficiente?
3. qual benefício o padrão oferece?
4. qual complexidade ele introduz?
5. como sua necessidade poderá evoluir?

## Tecnologia

Os padrões descritos nesta categoria devem permanecer conceitualmente independentes de uma linguagem ou framework específico.
