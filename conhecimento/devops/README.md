# DevOps

## Finalidade

Esta categoria reúne conhecimentos relacionados à construção de um fluxo confiável entre desenvolvimento, entrega, implantação e operação de software.

DevOps não deve ser reduzido a:

- uma ferramenta;
- um pipeline;
- automação;
- infraestrutura;
- uma equipe específica.

DevOps representa uma forma de integrar desenvolvimento e operação para aumentar a capacidade de entregar e operar software com segurança, qualidade e previsibilidade.

## Escopo

A categoria aborda:

- princípios de DevOps;
- ambientes;
- configuração;
- integração contínua;
- entrega contínua;
- pipelines;
- infraestrutura;
- automação;
- implantação;
- releases;
- rollback;
- recuperação;
- observabilidade;
- confiabilidade;
- capacidade;
- incidentes;
- operação;
- melhoria contínua.

## Princípio geral

A squad deve buscar:

> tornar o caminho entre uma mudança e seu uso seguro em produção cada vez mais confiável, observável e repetível.

## Relação com outras camadas

### Agent

`devops-engineer` conduz as atividades especializadas relacionadas à entrega e operação.

### Skills

As skills operacionalizam competências como:

- release-strategy;
- release-planning;
- environment-management;
- deployment;
- rollback-and-recovery;
- observability;
- release-monitoring;
- incident-response.

### Workflows

DevOps participa principalmente de:

- arquitetura;
- desenvolvimento;
- qualidade;
- entrega;
- evolução.

## Segurança

DevOps deve trabalhar em conjunto com:

`security-engineer`

Automação não deve automatizar práticas inseguras.

## Qualidade

Uma implantação tecnicamente bem-sucedida não significa necessariamente que a release foi bem-sucedida.

É necessário avaliar:

- funcionamento;
- segurança;
- observabilidade;
- impacto;
- estabilidade;
- capacidade de recuperação.

## Resultado esperado

O produto deve possuir um caminho de entrega que seja:

- repetível;
- verificável;
- observável;
- seguro;
- recuperável;
- proporcional ao risco;
- sustentável.
