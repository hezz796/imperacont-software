# Conhecimento de Arquitetura

## Finalidade

Este domínio reúne conhecimentos utilizados para compreender e tomar decisões sobre a arquitetura de soluções de software.

Arquitetura deve estabelecer uma estrutura coerente para atender aos requisitos do produto, às restrições existentes e aos atributos de qualidade relevantes.

## Escopo

Este domínio contempla:

- princípios arquiteturais;
- arquitetura de sistemas;
- domínios e fronteiras;
- componentes e módulos;
- atributos de qualidade;
- APIs e contratos;
- integrações;
- arquitetura de dados;
- eventos e mensageria;
- resiliência;
- escalabilidade;
- observabilidade;
- decisões arquiteturais;
- trade-offs;
- evolução arquitetural.

## Arquitetura antes da tecnologia

Arquitetura não deve ser reduzida à escolha de tecnologias.

Uma decisão arquitetural deve partir de:

- problema;
- requisitos;
- contexto;
- restrições;
- riscos;
- atributos de qualidade;
- necessidade de evolução.

Tecnologias são meios para materializar decisões arquiteturais.

## Contexto

Não existe uma arquitetura universalmente melhor.

Uma solução adequada depende de fatores como:

- domínio;
- escala;
- criticidade;
- equipe;
- orçamento;
- requisitos regulatórios;
- integrações;
- segurança;
- disponibilidade;
- velocidade de mudança;
- horizonte do produto.

## Trade-offs

Toda arquitetura envolve compromissos.

Uma decisão pode melhorar determinado atributo e prejudicar outro.

Por isso, decisões arquiteturais devem tornar explícitos os principais trade-offs.

## Evolução

Arquitetura não deve ser considerada imutável.

À medida que:

- o produto cresce;
- o domínio muda;
- os requisitos mudam;
- os riscos aumentam;
- novas evidências surgem;

a arquitetura pode precisar evoluir.

## Relação com outros domínios

Arquitetura possui relação direta com:

- Produto;
- UX;
- Engenharia;
- Dados;
- Segurança;
- DevOps;
- Qualidade.

A arquitetura deve traduzir necessidades do produto em uma estrutura técnica sustentável sem antecipar complexidade desnecessária.
