# Modelos da Squad

Esta categoria reúne estruturas conceituais que ajudam a squad a organizar pensamento e comunicação.

## Finalidade

Os modelos servem para:

- estruturar análises;
- separar conceitos;
- identificar lacunas;
- organizar decisões;
- melhorar comunicação;
- evitar conclusões precipitadas;
- preservar relações entre elementos.

## Modelo não é workflow

Um modelo explica uma relação entre conceitos.

Um workflow define uma sequência operacional.

Por exemplo:

```text
MODELO
Problema → Hipótese → Evidência → Aprendizado

WORKFLOW
Etapa 1 → Etapa 2 → Etapa 3 → Gate → Etapa 4
```

O modelo pode ser utilizado dentro de diferentes workflows.

## Modelo não é regra absoluta

Um modelo é uma ferramenta de raciocínio.

Nem todo contexto exigirá todos os seus elementos.

## Uso

A squad deve utilizar modelos de forma proporcional ao problema.

Modelos devem aumentar clareza, não criar burocracia.

## Categorias

Os modelos desta pasta abrangem:

- descoberta;
- produto;
- UX;
- requisitos;
- riscos;
- decisões;
- arquitetura;
- qualidade;
- desenvolvimento;
- entrega;
- evolução.

## Princípio

Um bom modelo ajuda a fazer perguntas melhores antes de tomar decisões.
