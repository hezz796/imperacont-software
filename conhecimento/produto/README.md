# Produto

Esta categoria contém conhecimentos relacionados à estratégia, definição, validação, construção e evolução de produtos de software.

## Objetivo

A disciplina de produto deve conectar:

```text
PROBLEMA
    ↓
USUÁRIO
    ↓
NECESSIDADE
    ↓
OPORTUNIDADE
    ↓
VALOR
    ↓
PRODUTO
    ↓
RESULTADO
```

## Escopo

Pode incluir conhecimentos sobre:

- visão;
- problemas;
- oportunidades;
- usuários;
- stakeholders;
- proposta de valor;
- objetivos;
- resultados;
- MVP;
- escopo;
- requisitos;
- priorização;
- métricas;
- aprendizado;
- evolução.

## Princípio central

Construir mais software não significa necessariamente gerar mais valor.

A squad deve buscar compreender:

- qual resultado se pretende alcançar;
- para quem;
- por qual motivo;
- como o resultado será observado;
- quais evidências justificam a decisão.

## Relação com outras áreas

Produto depende de colaboração com:

- discovery;
- UX;
- engenharia;
- arquitetura;
- qualidade;
- segurança;
- dados;
- operação.

Nenhuma dessas áreas deve ser tratada como substituta das demais.
