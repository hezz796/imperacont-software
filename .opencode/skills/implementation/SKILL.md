# Implementation

## Objetivo

Transformar requisitos e decisões arquiteturais em software funcional, sustentável e verificável.

## Princípio

Implementar a solução definida sem introduzir mudanças de escopo ou arquitetura de forma silenciosa.

## Antes de implementar

Verificar:

- requisitos;
- critérios de aceitação;
- regras de negócio;
- arquitetura;
- decisões técnicas;
- dependências;
- riscos;
- testes existentes.

Inspecionar o projeto antes de modificar arquivos.

## Processo

1. compreender o contexto;
2. identificar o comportamento esperado;
3. localizar componentes afetados;
4. verificar padrões existentes;
5. avaliar impactos;
6. implementar;
7. testar;
8. revisar;
9. documentar mudanças relevantes.

## Código

Priorizar:

- clareza;
- simplicidade;
- coesão;
- baixo acoplamento;
- responsabilidade bem definida;
- consistência;
- legibilidade;
- testabilidade.

Evitar:

- duplicação desnecessária;
- abstrações prematuras;
- código morto;
- complexidade sem benefício;
- alterações não relacionadas.

## Requisitos

Não substituir requisitos por interpretação pessoal.

Quando houver ambiguidade relevante:

- identificar;
- registrar;
- perguntar ou solicitar decisão;
- não inventar comportamento.

## Arquitetura

Respeitar as fronteiras arquiteturais estabelecidas.

Se a implementação exigir mudança arquitetural significativa:

1. interromper a decisão silenciosa;
2. identificar o impacto;
3. propor alternativas;
4. registrar a decisão apropriada.

## Segurança

Considerar desde a implementação:

- validação;
- autorização;
- autenticação;
- proteção de dados;
- tratamento de erros;
- segredos;
- dependências;
- logs.

## Testabilidade

Implementações devem permitir verificação adequada.

Criar ou atualizar testes quando necessário.

## Saída esperada

Produzir:

1. implementação;
2. testes relacionados;
3. alterações necessárias;
4. decisões relevantes;
5. riscos;
6. pendências;
7. documentação necessária.
