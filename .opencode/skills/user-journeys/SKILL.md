# User Journeys

## Objetivo

Representar como um usuário alcança determinado objetivo, incluindo contexto, etapas, decisões, dificuldades e resultados.

## Princípio

A jornada deve representar a experiência e o objetivo do usuário, não apenas as funcionalidades do sistema.

## Elementos

Identificar:

- usuário;
- objetivo;
- contexto;
- gatilho;
- etapas;
- ações;
- decisões;
- pontos de contato;
- expectativas;
- dificuldades;
- emoções, quando relevantes;
- resultados;
- exceções;
- término.

## Jornada atual

Quando necessário, documentar o estado atual:

- como o processo funciona hoje;
- ferramentas utilizadas;
- etapas manuais;
- problemas;
- retrabalho;
- esperas;
- transferências;
- falhas.

## Jornada futura

Definir a experiência desejada sem assumir imediatamente a implementação.

Identificar:

- melhorias;
- simplificações;
- novos comportamentos;
- novos pontos de interação;
- automações desejáveis;
- decisões necessárias.

## Tarefas

Para cada tarefa importante:

- objetivo;
- pré-condições;
- ação;
- informação necessária;
- decisão;
- resultado esperado;
- exceções.

## Pontos de fricção

Identificar:

- confusão;
- excesso de etapas;
- espera;
- repetição;
- erros;
- falta de informação;
- inconsistência;
- mudança de contexto.

## Oportunidades

Relacionar cada ponto de fricção a oportunidades de melhoria.

Não assumir que toda fricção deve ser resolvida por software.

## Validação

Jornadas importantes devem ser confrontadas com evidências de pesquisa ou validação com usuários quando possível.

## Saída esperada

Produzir:

1. usuário;
2. objetivo;
3. contexto;
4. jornada atual;
5. pontos de fricção;
6. oportunidades;
7. jornada futura;
8. exceções;
9. hipóteses;
10. pontos que precisam de validação.
