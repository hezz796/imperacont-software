# Design System Thinking

## Objetivo

Estabelecer padrões reutilizáveis de experiência e interface quando a complexidade ou escala do produto justificar.

## Princípio

Não criar um design system por obrigação.

O sistema deve resolver problemas reais de:

- consistência;
- reutilização;
- velocidade;
- qualidade;
- manutenção;
- evolução.

## Elementos

Considerar:

- princípios;
- tokens;
- tipografia;
- espaçamento;
- cores;
- componentes;
- padrões;
- estados;
- comportamento;
- conteúdo;
- acessibilidade.

## Componentes

Cada componente relevante deve possuir:

- finalidade;
- comportamento;
- estados;
- propriedades;
- variações;
- regras de uso;
- acessibilidade.

## Consistência

Identificar padrões repetidos e evitar múltiplas soluções para o mesmo problema sem justificativa.

## Evolução

Um padrão deve poder evoluir sem quebrar silenciosamente suas utilizações.

Mudanças relevantes devem ser documentadas.

## Produto versus tecnologia

O conceito de design system deve permanecer separado da implementação específica.

A forma de implementação será definida posteriormente pela arquitetura e engenharia.

## Saída esperada

Produzir:

1. princípios;
2. padrões;
3. componentes;
4. estados;
5. regras;
6. requisitos de acessibilidade;
7. documentação;
8. decisões;
9. itens candidatos à reutilização.
