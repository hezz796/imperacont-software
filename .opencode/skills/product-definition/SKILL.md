# Product Definition

## Objetivo

Transformar os resultados de Discovery em uma definição de produto suficientemente clara para orientar UX, arquitetura, desenvolvimento, testes e entrega.

## Princípio

A definição de produto deve responder:

- por que o produto existe;
- para quem;
- qual problema resolve;
- qual valor entrega;
- o que precisa fazer;
- como será avaliado;
- o que está fora do escopo.

## Entradas

Utilizar:

- discovery;
- problema;
- oportunidades;
- usuários;
- hipóteses;
- validações;
- requisitos;
- regras de negócio;
- capacidades;
- backlog;
- métricas;
- restrições.

## Estrutura

### Visão

Definir o resultado desejado para o produto.

### Público

Definir os usuários e partes interessadas relevantes.

### Problema

Descrever o problema que justifica o produto.

### Proposta de valor

Explicar qual valor o produto pretende entregar.

### Capacidades

Definir as principais capacidades necessárias.

### Requisitos

Consolidar requisitos funcionais e não funcionais relevantes.

### Regras

Consolidar regras de negócio.

### Experiência

Registrar necessidades e princípios relevantes para UX.

### MVP

Definir o menor escopo capaz de:

- entregar valor;
- testar hipóteses;
- reduzir riscos;
- gerar aprendizado.

### Métricas

Definir como o resultado será avaliado.

### Não objetivos

Registrar explicitamente o que não será feito.

### Restrições

Registrar restrições relevantes.

### Riscos

Consolidar riscos conhecidos.

## Consistência

Verificar se existe coerência entre:

`Problema → Usuário → Valor → Capacidade → Requisito → Backlog → Métrica`

Se houver quebra significativa nessa cadeia, investigar antes de avançar.

## Gate de Product Definition

Antes de avançar para UX e Arquitetura, verificar:

- problema compreendido;
- usuários identificados;
- proposta de valor definida;
- escopo inicial definido;
- requisitos suficientemente claros;
- regras relevantes identificadas;
- métricas estabelecidas;
- riscos conhecidos;
- não objetivos registrados;
- principais incertezas explicitadas.

## Decisões

O resultado pode ser:

- aprovado;
- aprovado com ressalvas;
- retornar para discovery;
- retornar para validação;
- reformular;
- interromper.

## Saída esperada

Produzir um Product Definition contendo:

1. visão;
2. usuários;
3. problema;
4. proposta de valor;
5. capacidades;
6. requisitos;
7. regras;
8. MVP;
9. backlog inicial;
10. métricas;
11. não objetivos;
12. restrições;
13. riscos;
14. dependências;
15. questões em aberto;
16. decisão de avanço.
