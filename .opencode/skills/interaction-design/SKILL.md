# Interaction Design

## Objetivo

Definir como o usuário interage com o produto e como o produto responde às ações.

## Princípio

Uma interface não deve apenas apresentar elementos visuais.

Cada interação deve possuir:

- intenção;
- ação;
- resposta;
- estado;
- consequência.

## Fluxos

Para cada fluxo relevante, identificar:

- início;
- objetivo;
- pré-condições;
- ações;
- decisões;
- resultados;
- exceções;
- término.

## Estados

Considerar, conforme o contexto:

- inicial;
- vazio;
- carregando;
- sucesso;
- erro;
- indisponível;
- parcialmente concluído;
- bloqueado;
- sem permissão;
- alterado;
- confirmado.

Não projetar apenas o estado ideal.

## Feedback

O sistema deve comunicar adequadamente:

- o que aconteceu;
- o que está acontecendo;
- o que será necessário fazer;
- se uma ação foi concluída;
- se ocorreu um problema.

## Erros

Mensagens de erro devem:

- explicar o problema;
- evitar linguagem técnica desnecessária;
- indicar como corrigir quando possível;
- preservar o trabalho realizado;
- não culpar o usuário.

## Formulários

Considerar:

- campos necessários;
- campos opcionais;
- validação;
- máscaras;
- mensagens;
- valores padrão;
- preenchimento;
- confirmação;
- recuperação de erros.

## Consistência

Manter padrões consistentes para:

- controles;
- nomenclatura;
- navegação;
- feedback;
- estados;
- ações.

## Ações destrutivas

Para ações potencialmente irreversíveis:

- informar consequência;
- diferenciar da ação comum;
- solicitar confirmação quando apropriado;
- oferecer recuperação quando possível.

## Saída esperada

Produzir:

1. fluxos;
2. comportamentos;
3. estados;
4. transições;
5. feedbacks;
6. mensagens;
7. regras de interação;
8. exceções;
9. requisitos de consistência.
