# Opportunity Analysis

## Objetivo

Determinar se um problema representa uma oportunidade relevante para intervenção e se existe justificativa suficiente para avançar na investigação ou construção de uma solução.

## Princípio

Uma oportunidade não deve ser considerada válida apenas porque:

- existe um problema;
- existe uma demanda;
- uma solução parece interessante;
- uma tecnologia permite implementá-la.

É necessário avaliar valor, evidência e contexto.

## Dimensões da análise

Avaliar, quando aplicável:

### Necessidade

- intensidade do problema;
- frequência;
- urgência;
- impacto;
- quantidade de pessoas afetadas.

### Valor

- valor para usuários;
- valor para negócio;
- redução de custos;
- aumento de receita;
- redução de riscos;
- melhoria de produtividade;
- melhoria de experiência.

### Alternativas

Investigar:

- concorrentes;
- soluções internas;
- processos manuais;
- planilhas;
- serviços;
- produtos substitutos;
- processos existentes.

A ausência de software também deve ser considerada uma alternativa.

### Viabilidade

Avaliar:

- viabilidade operacional;
- viabilidade técnica;
- viabilidade econômica;
- disponibilidade de dados;
- dependências;
- restrições legais ou regulatórias;
- capacidade de execução.

### Riscos

Identificar:

- riscos de mercado;
- riscos de adoção;
- riscos técnicos;
- riscos financeiros;
- riscos operacionais;
- riscos de segurança;
- riscos de privacidade;
- riscos regulatórios.

## Evidências

Para cada afirmação relevante, identificar sua base:

- dado;
- pesquisa;
- entrevista;
- observação;
- fonte externa;
- experiência operacional;
- hipótese.

Não apresentar estimativas como fatos.

Quando dados externos forem necessários, realizar pesquisa adequada e registrar as fontes.

## Matriz de oportunidade

Quando apropriado, classificar cada oportunidade segundo:

- impacto potencial;
- evidência disponível;
- urgência;
- esforço;
- risco;
- alinhamento estratégico.

A classificação deve ser explicada e não apenas atribuída.

## Decisões possíveis

A análise pode resultar em:

### Avançar

Existe evidência suficiente para continuar.

### Validar

A oportunidade parece relevante, mas existem incertezas importantes.

### Reformular

O problema ou oportunidade precisa ser redefinido.

### Adiar

A oportunidade pode ser válida, mas não é prioritária neste momento.

### Encerrar

As evidências não justificam continuidade.

## Saída esperada

Produzir:

1. oportunidade analisada;
2. problema relacionado;
3. usuários afetados;
4. valor potencial;
5. alternativas existentes;
6. evidências;
7. premissas;
8. riscos;
9. viabilidade preliminar;
10. principais incertezas;
11. recomendação;
12. próximos passos.
