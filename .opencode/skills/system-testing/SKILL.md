# System Testing

## Objetivo

Avaliar o comportamento do sistema completo em relação aos requisitos e atributos de qualidade definidos.

## Princípio

O sistema deve ser avaliado como produto integrado, não apenas como conjunto de componentes isolados.

## Processo

1. Identificar requisitos relevantes.
2. Preparar ambiente representativo.
3. Preparar dados.
4. Definir cenários.
5. Executar fluxos completos.
6. Validar resultados.
7. Verificar comportamentos excepcionais.
8. Avaliar atributos de qualidade.
9. Registrar falhas.
10. Consolidar evidências.

## Abrangência

Quando aplicável:

- fluxos ponta a ponta;
- regras de negócio;
- integrações;
- persistência;
- interfaces;
- autenticação;
- autorização;
- erros;
- desempenho;
- confiabilidade;
- compatibilidade.

## Regras

- Priorizar fluxos de negócio críticos.
- Utilizar condições representativas.
- Não confundir teste de sistema com teste exclusivamente de interface.
- Considerar interações entre diferentes partes do produto.

## Saída

Produzir:

- cenários executados;
- resultados;
- falhas;
- evidências;
- requisitos verificados;
- riscos remanescentes.
